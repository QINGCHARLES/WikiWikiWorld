# API status codes — release 2026-11-24

The owner asked to fix the API's 401 handling, then to push and deploy.

## Change

- `a4883a3`: `UseStatusCodePagesWithReExecute` now applies only outside `/api`.
  - Before, it re-executed every empty API error response against the not-found page. A missing or bad token gave
    404 on GET, and 400 on POST, because that page has no POST handler.
  - API clients now get 401, 403 and 404 exactly as the controller sends them.
  - Browser pages still get the not-found page.
- `5ea6195`: `appsettings.Development.json` is marked `CopyToPublishDirectory="Never"`.
  - That file is git-ignored but sits in the main checkout's project folder. A container published from there
    shipped it, including the **development** JWT secret.
  - The affected images:
    - `release-20261124T050232Z-5458ba252aae`, published by another session, which ran in production
      05:18–06:03 UTC.
    - `release-20261124T063950Z-a4883a374fd7`, published here and never deployed.
  - Production never loaded the file, because it does not run as Development. Anonymous pulls from GHCR are
    refused, so the package is private.
  - Images published from worktrees (`242e490`, `ab1c6e4`) were clean.
- `cabd573`: release record only.

No database change. Nothing under `deploy/` changed.
