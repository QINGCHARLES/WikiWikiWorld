# Header helper

`/wiki:header-helper` is an anonymous, browser-only Razor Page shared by the wikis. The article editor links to it in a new tab so unsaved article text is preserved. It replaces the core workflow of the WinUI cropper at `LoveRats.HeaderCropper`; that app remains unchanged.

## Workflow

Open, drop, or paste a picture; adjust the crop using pointer handles, arrows (Shift = 10 source pixels), or numeric fields. Lock the current aspect ratio, zoom and scroll, or reset to the full source. Choose top/center/bottom focus and inspect phone, tablet and desktop previews. Enter an article slug and quality, then select **Download header**: it encodes the AVIF (only when pixels or quality changed since the last encode) and starts the download. The article slug starts blank and is never inferred from the source filename. Downloading and copying markup require an entered slug; blank/whitespace input shows an inline error and focuses the field. Clearing the slug also clears generated markup. The actual encoded size is shown after encoding; output above the existing 10 MiB upload limit gets a warning and is not downloaded automatically.

The image URL field and failed remote imports explain that some websites block direct imports and the user should download the image and open/drop the local file. There is no server fetch proxy, upload endpoint, temporary image storage, or automatic publication. File selection is local processing, not a wiki upload. The final AVIF can be uploaded through the existing file-article workflow; generated markup is `{{HeaderImage file:header-for-<slug>}}`, the file article's URL slug without the `.avif` extension (HeaderImage slugifies its value, so an extension would never resolve), and must be edited if the file article gets a different slug.

## Implementation and bounds

- Page: `Pages/Wiki/HeaderHelper.cshtml(.cs)`. Script: `wwwroot/js/header-helper.js`; cancellable codecs: `header-helper-worker.js`. Styling is registered in `SiteStylesheetCatalog` and scoped to the helper.
- Modern browsers with module workers, WebAssembly, OffscreenCanvas, and createImageBitmap are required. No-JavaScript and unsupported-browser messages explain the requirement. Chromium is verified; Firefox, Safari and physical phones still need verification.
- Native browser decoding handles JPEG, PNG, WebP, AVIF, GIF (first frame) and BMP. HEIC/HEIF falls back to the lazy-loaded libheif WASM bundle. EXIF orientation follows the browser decoder; unusual profiles, HDR and all HEIF variants are not guaranteed equivalent to the desktop ImageMagick pipeline.
- Input limit: 50 MiB. Decoded dimensions: at most 40 million pixels and 16,384 pixels per side. This is a browser-specific bound, lower than the desktop app's 100 MP limit. The native decoder allocates before its dimensions are available, and smaller images can still exhaust memory on constrained devices. It is not a guarantee that every device supports the limit.
- An editor proxy is bounded to 1,800 pixels per side. The retained full-resolution bitmap supplies native-resolution export. Preview geometry follows `css/components/media.css` and the desktop reference presets: 320×690, 800×1280 and 1920×1080; hero max-width approximation 1,872 px; 26rem / 52vw / 60vh height; the same focus, bottom fade, edge feather, title-overlap and 1.025 resting scale. Bar and title are illustrative; paper shader and scrolling parallax are excluded.
- AVIF is prepared only on request, not continually during crop changes. It is 8-bit, sRGB canvas pixels, YUV 4:2:0, speed 6, default quality 65. Quality scales are not promised byte-equivalent to ImageMagick. A slow encode can outlast the click's user activation, so the automatic download may be blocked; a fallback **Download didn't start? Save header** link to the same blob then appears, and a direct click on it is always allowed.
- Each decode/export worker is terminated after completion or cancellation, releasing codec memory. A failed import preserves the prior image/crop. Pixel or quality changes invalidate old exports. Slug/focus changes update filename/markup without re-encoding.
- Remote imports use anonymous browser fetch, a whole-operation 45-second timeout and a streamed byte limit. CORS, HTTPS mixed-content and authentication restrictions apply. No third-party runtime CDN is used.
- The worker URL is content-versioned by Razor. Vendor URLs are versioned directories. `.wasm` and `.mjs` are excluded from the article catch-all so static middleware serves them. No cross-origin isolation headers or server-native libraries are required.

## Verification (2026-10-28)

`dotnet test tests/WikiWikiWorld.Web.Tests -c Release` passes all 235 tests, including four focused routing/stylesheet checks. Release compilation passes with existing ImageSharp dependency advisory warnings. Both authored JavaScript files pass `node --check`.

Real Chromium checks: WebP import and 800×400 AVIF export decoded back to 800×400; HEIC sample import (1280×854), cropped to 640×360 and downloaded as valid AVIF; pointer and keyboard crop movement; ratio-preserving numeric resize; focus markup; blocked URL guidance; invalid-file recovery; cancellation; stale-download invalidation; branding on Magazedia/Cinepedia; desktop/mobile layout without horizontal overflow; and JavaScript-disabled messaging with disabled controls. Network inspection confirmed no non-GET requests during local HEIC import/export. No production deployment or content/database writes were performed. This page has no mutation handlers, so there is no new antiforgery or persistence contract.
